## What the numbers imply

Privacy passes and fidelity and utility both fail. That is the signature of data generated from hand-written option lists with no real input: it cannot leak anyone, and it cannot represent anyone either. The generator draws one or two of nine conditions and one of three age bands uniformly at random, so the synthetic cohort has the wrong age profile, a fraction of the conditions real people report, and no real co-occurrence structure -- retrieval over it does worse than guessing its most common conditions.

As it stands the batch is not a stand-in for real users in any agent evaluation. Whether to regenerate it (for example, seeded from real aggregate distributions) or to exclude it from evaluation entirely is the open design choice on the deck; these numbers are the evidence for that decision, not the decision itself.

## Method notes

- Both cohorts go through the shared condition taxonomy first, so spelling (`low_income` vs `Limited Income`) is never counted as a difference.
- Fidelity pass/fail is a bootstrap test, not a chosen threshold: an attribute fails only if it differs from the real cohort by more than chance would at these sample sizes.
- The TSTR pass line (80% of TRTR) is a common rule of thumb, stated so it can be argued with. At this cohort size even the real pool only modestly beats a popularity guess, so the reference itself is weak.
- Privacy uses both how the data was made and how close it sits to real records; neither alone is conclusive.

## Downstream utility (TSTR) — FAIL

FAIL — TSTR hit@3 12% vs TRTR 36% (ratio 0.33, pass ≥ 0.8) on 194 cases

Test cases: 194 held-out conditions from 32 real people with two or more named conditions. hit@3, 10 nearest neighbours.

| pool | hit@3, all hidden conditions | hit@3, hidden condition exists in synthetic vocabulary |
|---|---|---|
| TRTR — other real users | 36% (70/194; 95% CI 30%–43%) | 52% (37/71; 95% CI 41%–63%) |
| TSTR — synthetic users | 12% (23/194; 95% CI 8%–17%) | 32% (23/71; 95% CI 23%–44%) |
| popularity, real | 32% (62/194; 95% CI 26%–39%) | |
| popularity, synthetic | 15% (29/194; 95% CI 11%–21%) | |

**TSTR / TRTR = 0.33** (proposed pass: ≥ 0.8).

- The synthetic pool knows 9 conditions. A hidden condition outside those can never be recovered from it, whatever the matching does; the right-hand column removes that handicap to ask whether the pool carries real co-occurrence structure at all.
- Cases with no usable neighbour (nobody who shares a remaining condition and holds one the person lacks), so the guess fell back to popularity: TRTR 0, TSTR 12.
- Several cases come from the same person, so they are not independent; the intervals are somewhat narrower than they should be. With this few real people, read the direction, not the decimals.

Every read is inside `purge()`, which only selects synthetic accounts by their `synthetic+…@autinerary.dev` address in order to delete them. Profiles are built from hard-coded option lists with `Math.random()`; no real record is ever read, so none can have been copied.
