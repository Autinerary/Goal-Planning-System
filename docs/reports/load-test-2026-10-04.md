# Load test baseline, 4 October 2026

Riipen Labs (Group 2) asked for "a program of testing" for problems that only
show up when many people use Autinerary at the same time. This is the first
run of that program: signed-out visitors only, up to 50 at once. Scripts and
how to repeat it are at the end.

## What we found

- **No errors at any level tested** (5, 10, 25 and 50 visitors at once,
  about 900 requests).
- **Pages and the API stay fast.** The landing and sign-up pages (served by
  Vercel's CDN) and the API's `/health` stay under 0.25 s at the 95th
  percentile at every level.
- **ResourceHub search is the first thing to slow down.** Its typical time
  (median) only goes from 0.3 s to 0.5 s, but the slowest 5% go from about
  0.5 s at 25 visitors to 2.1 to 2.5 s at 50. Search runs a database query
  (and, for typed searches, an embedding call) on every request, so it is the
  first place to look before a launch push. Likely fixes: cache common
  category searches for a minute, and check the Supabase connection pool.
- The slower 95th percentiles at 5 visitors (about 1.9 s for search) are cold
  starts: the first requests after a quiet period. They disappear at 10.

## Not run yet

- **More than 50 visitors at once.** Stopped here so the test could not
  degrade the live service for real users. The next step is a run at 100 and
  200, ideally at a quiet time or against a staging copy.
- **Path generation under load** (`generate`: several new accounts finishing
  setup at the same moment). This is the heaviest operation: about a minute
  per path, run on one API server, with an AI model. The API code notes
  about 160 s per path at five at once, but that has not been re-measured
  since. It costs a few cents per run and leaves the QA accounts in place.

## How to repeat it

From `backend/`:

```
python -m scripts.load_test browse                          # 5, 10, 25, 50 visitors, 20 s each
python -m scripts.load_test browse --stages 100,200         # higher levels
python -m scripts.load_test generate --users 5              # 5 path generations at once
python -m scripts.load_test browse --report ../docs/reports/load-test-YYYY-MM-DD.md
```

The browse test writes nothing and stops by itself after any stage where more
than 10% of requests fail. The generate test creates QA accounts named
`test.account+riipen-load-*@test.com`.
